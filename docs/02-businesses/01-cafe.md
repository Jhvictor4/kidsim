# 카페 업종 명세

문서 ID: BIZ-CAFE · 버전: 2.0 · 상태: MVP 구현 기준 · 기준일: 2026-11-11

[문서 트리](../README.md) · [업종 선택](README.md) · [카페 스토리보드](../03-experience/04-storyboard-cafe.md)

## 1. 플레이어의 역할

작은 카페의 사장이 되어 손님의 취향, 주문 대기열, 추출 일관성, 원재료 준비, 영업 약속을 함께 관리한다. 장식을 바꾸는 만족감과 실제로 다시 찾아오는 손님을 만드는 운영을 연결한다. 첫 매출보다 **한 번 만족한 손님에게 다음에도 같은 품질을 제공하는 것**을 핵심 과제로 삼는다.

MVP의 제품은 `CAFE_COFFEE_01` 기본 커피 한 종류다. 연구 결과로 같은 제품의 배합·제조 규격을 바꾸며 새 상품 수십 개를 추가하지 않는다. 맛의 선호와 제품 결함은 다르게 처리한다. 진한 맛을 싫어하는 손님이 있다고 해서 모든 손님에게 품질이 낮은 커피로 기록하지 않는다.

## 2. MVP 범위와 시작 상태

| 항목 | 구현 범위 |
|---|---|
| 제품 | 기본 커피 1종, 활성 레시피 버전 1개 |
| 시작 자산 | 업종 필수 장비·판매대·기본 좌석·간판, 공통 시작 자금 80 TC |
| 고객 | 커피 수요를 가진 NPC. 빠른 수령·취향·공간 분위기 등 선호는 공통 고객 정의를 사용 |
| 핵심 조작 | 원재료 준비, 주문 수락, 제조 우선순위, 품질 확인, 전달, 배치, 영업표 관리 |
| 연구 | 추출 일관성 / 취향 배합 |
| 선택 사건 | 원재료 특성 변화 / 단체 주문 요청 |
| 업그레이드 | 기본 운영, 동선 정리, 전문 운영의 3단계 |
| 범위 밖 | 실제 카페 프랜차이즈 계약, 직원 임금 협상, 원두 상품 거래, 플레이어 간 주문 판매 |

기본 거래는 매출 16 TC·변동원가 6 TC·작업 30초이며 공헌이익은 10 TC다. 운영비·연구·사건 대응비를 차감한 순이익과 구분한다. 가격·원가·처리시간·예약 비용은 [경제 원본](../01-game/06-economy-and-items.md)의 `CAFE_COFFEE_01` 행을 따른다. 연구와 장비가 만드는 효과도 같은 원본에서 읽으며 문서나 화면에 별도 숫자를 넣지 않는다. DG 외형은 처리 속도·맛·고객 선택 확률을 높이지 않는다.

## 3. 실제 플레이 흐름

1. 영업 전에 재고, 활성 레시피, 장비 상태, 다음 예약을 확인한다.
2. 영업 시작을 선언하면 커피 수요 NPC의 후보 가게에 포함된다.
3. 주문 수락 시 원재료 비용·처리 슬롯과 필요한 운영비 예산을 예약한다. 착수 시 원재료 비용을 소비하고 운영비는 유상 운영 시간에 따라 차감한다. 가격과 약속 시간은 수락 당시 값을 보존한다.
4. 제작 중 플레이어는 우선순위·작업 동선·품질 대응을 선택한다. 연속 클릭 수는 품질을 결정하지 않는다.
5. 주문의 제품 버전과 제조 상태로 품질 결과를 산출하고 전달한다.
6. 완료 거래를 한 번 정산하고 고객 경험을 기록한다.
7. 품질 원인과 고객 선호를 보고 다음 배치, 연구, 영업 계획을 조정한다.

### 업종 내부 공정

아래는 공통 거래 상태 안의 카페 작업 단계다. 거래의 생성·완료·취소 상태는 [공통 구현 명세](../04-implementation/01-engine-neutral-spec.md)가 소유한다.

| 공정 | 플레이어가 바꾸는 것 | 확정 기록 |
|---|---|---|
| 준비 | 다음 주문에 사용할 레시피와 재고 준비 | 준비 수량, 활성 레시피 버전 |
| 추출 | 허용된 작업 순서와 재작업 선택 | 사용한 재료 배치, 장비 상태, 작업 체크 |
| 검수 | 그대로 전달 / 재작업 / 고객에게 취소 제안 | 측정 결과, 선택, 추가 비용 동의 |
| 전달 | 준비된 주문을 올바른 고객에게 인계 | 거래 ID, 전달 시각, 최종 제품 버전 |

재작업은 새 손님이나 새 매출을 만들지 않는다. 추가 재료를 쓰면 원본 주문 아래 비용 항목으로 기록한다. 결함이 있는 제품을 취소·환불한 경험과 취향이 맞지 않는 경험은 고객 기록에서 구분한다.

## 4. 품질과 손님이 끊기는 이유

카페의 결과는 레시피 자체의 완성도, 원재료 상태, 제조 일관성, 장비 상태, 약속한 대기시간, 고객 취향 적합성으로 설명한다. 전체 품질·명성 계산은 [운영과 연구](../01-game/03-operations-quality-rnd.md), [명성과 경쟁](../01-game/04-reputation-and-competition.md)을 따른다.

| 상황 | 고객에게 보이는 결과 | 회복 행동 |
|---|---|---|
| 예정 영업시간에 문을 열지 않음 | 약속된 방문·예약을 처리하지 못함 | 다음 영업표 수정, 확정 주문 정리, 정상 영업 경험 축적 |
| 재료 특성이 달라졌는데 규격을 확인하지 않음 | 같은 메뉴의 편차가 커짐 | 테스트 배치, 레시피 검증, 영향받은 주문 재처리 |
| 주문을 무리하게 수락 | 예상 대기시간과 실제 대기시간이 벌어짐 | 수락량 조절, 정직한 시간 안내, 동선 개선 |
| 인기 취향 변화에 계속 대응하지 않음 | 현재 제품의 취향 적합성이 낮아짐 | 조사와 배합 연구, 다른 고객층 선택 |
| 장비·위생 관리 경고를 방치 | 결함·운영 중단 위험이 증가 | 해당 원인을 정비하고 재검증 |

레시피가 오래됐다는 이유만으로 맛 점수를 매일 깎지 않는다. 정상적인 제조 조건을 유지하면 제품 품질은 유지될 수 있다. 연구 부족은 관측된 문제를 해결하지 못하거나 시장 선호 변화에 적응하지 못한 결과로 드러난다.

## 5. 연구 두 갈래

| 연구 ID | 질문 | 수행 | 완료 증거 | 적용 |
|---|---|---|---|---|
| `RND_CAFE_CONSISTENCY` | 같은 조건에서 결과가 일정한가? | 기준 배합으로 테스트, 편차 원인 선택, 개선 배치 비교 | 동일 조건의 전후 결과가 기준을 충족 | 이후 주문의 제조 규격 버전 변경 |
| `RND_CAFE_TASTE` | 어떤 고객층에 맞는 맛인가? | 고객 요구 확인, 후보 배합 선택, 제한 시음 평가 | 목표 고객의 적합성 평가와 비용 확인 | 이후 주문의 취향 속성 변경 |

연구는 단계당 20 TC와 활동 90초, 공유 생산 슬롯을 사용한다. 각 갈래 최대 3단계, 선행 사업 레벨 1·2·3이다. 연구는 기존 주문을 정리하고 `CLOSED`에서 시작·진행한다. 연구 시작 전 비용과 작업 점유, 확정된 다음 영업 약속과의 충돌을 보여준다. 정상적으로 공지한 연구 휴업 자체에는 명성 벌점이 없다. 결과는 승인 후 다음 주문부터 적용한다. 이미 수락한 주문의 제품을 중간에 바꾸지 않는다. 연구 실패도 관측 결과를 보존한다. 연구 완료 자체에는 TC·XP를 지급하지 않으며, 개선 효과는 이후 정상 고객 경험으로 확인한다.

## 6. 선택 사건

### EV_CAFE_01 원두가 달라졌다

발생 조건은 신규 원재료 배치의 특성이 현재 레시피 허용 범위를 벗어났고, 동일 사건이 진행 중이지 않은 경우다. NPC 납품 담당의 대사 예시는 “이번 재료는 지난번과 특성이 조금 달라요. 첫 배치를 확인해 볼까요?”다.

| 선택 | 즉시 바뀌는 것 | 뒤에 확인할 결과 |
|---|---|---|
| A. 테스트 후 조정 | 테스트 비용·시간을 사용, 확인 전 수락량 제한 | 규격 검증 후 일관성 회복 |
| B. 소량 시험 판매 | 해당 고객에게 시험 제공임을 알리고 제한된 수량 판매 | 동의한 고객의 평가로 개선 근거 확보 |
| C. 기존 규격 유지 | 즉시 운영 유지, 화면에 알려진 편차 위험 보존 | 실제 제조 편차가 다음 고객 경험에 반영 |

시험 판매는 정상 품질을 약속한 기존 주문에 몰래 적용할 수 없다. C를 선택했다는 이유만으로 정해진 실패를 강제하지 않으며, 알려진 조건으로 산출한 결과를 보여준다.

### EV_CAFE_02 단체 주문을 받을까

발생 조건은 고객 무리가 유입되고 기존 대기열과 처리 능력의 차이가 의미 있게 존재하는 경우다. NPC는 주문 수량과 원하는 수령 시각을 함께 제시한다.

| 선택 | 약속 | 결과를 결정하는 행동 |
|---|---|---|
| A. 가능한 시간으로 수락 | 계산된 대기시간을 고지하고 단체 주문 수락 | 기존 주문과 함께 약속 시간을 지킴 |
| B. 나누어 수락 | 가능한 일부 수량과 후속 수령 시간을 협의 | 합의된 분할 수량·시간을 각각 이행 |
| C. 이번 주문 거절 | 새 주문을 만들지 않음 | 기존 고객 경험 유지, 단체 매출 기회는 다른 후보로 이동 |

단체 수요도 각각 고유 ID가 있는 개별 주문으로 처리한다. MVP는 작업 1건과 대기 1건을 넘겨 수락하지 못한다. B는 일부 개별 주문만 수락하는 선택이며 한 주문을 쪼개 여러 매출로 만들지 않는다. 거절 자체에 명성 벌점을 주지 않는다. 불가능한 약속을 확정한 뒤 어기는 경우는 확정 주문의 불이행으로 처리한다. 다른 플레이어의 가게로 간 수요를 복제해 나에게도 주지 않는다.

### 사건 비용과 시간의 원본 연결

| 사건·선택 | 추가 직접비 | 추가 작업 | 추가 운영비 예산 | 정산·효과 |
|---|---:|---:|---:|---|
| EV_CAFE_01 A | 2 TC | 30초 | 1 TC | 검사 결과가 기준을 통과하면 해당 재료 원인의 경고 해결 |
| EV_CAFE_01 B | 0 TC | 0초 | 추가 고정분 없음 | 동의한 실제 주문만 기본 원가·시간·매출로 처리 |
| EV_CAFE_01 C | 0 TC | 0초 | 추가 고정분 없음 | 알려진 편차 원인을 유지하고 실제 결과로 평가 |
| EV_CAFE_02 A·B | 0 TC | 사건 자체 0초 | 수락할 개별 주문의 필요액 | 각 주문 정상 완료 때만 매출 지급 |
| EV_CAFE_02 C | 0 TC | 0초 | 0 TC | 신규 주문 생성 없음 |

직접비는 사건 작업 착수 전 예약하고 착수 시 소비한다. 운영비 예산은 별도 즉시 수수료가 아니라 실제 유상 운영에 사용할 예약액이다. 추가 30초 대응은 공통 생산 슬롯을 사용하는 `EVENT_WORK`이며 연구 단계·XP를 지급하지 않는다. 예산이 부족하면 A를 비활성화하고 B·C의 시간 연장 없는 대안을 남긴다. B는 고객이 동의한 경우에만 적용한다. 수치의 권위는 [경제 원본의 사건 설정](../01-game/06-economy-and-items.md)에 있다.

## 7. 업그레이드와 공간

| 단계 | 운영상 의미 | 해금 효과 | 교육 관찰 |
|---|---|---|---|
| T1 기본 운영 | 주문 한 흐름을 안정적으로 완수 | `EQ_CAFE_1` 시작 지급 | 매출과 순수익의 차이 이해 |
| T2 동선 정리 | 대기·제작·전달의 충돌 감소 | `EQ_CAFE_2`, 120 TC·사업 레벨 2 | 병목이 어디서 발생하는지 설명 |
| T3 전문 운영 | 일관성 또는 고객 취향 전략 강화 | `EQ_CAFE_3`, 300 TC·사업 레벨 3 | 같은 돈으로 무엇을 개선할지 비교 |

설비 구매만으로 작업 슬롯이나 처리 속도가 증가하지 않는다. 도구의 품질 상한과 실제 규격·검수 결과를 분리한다. 업그레이드의 상품 ID·가격·상한은 [경제와 아이템](../01-game/06-economy-and-items.md)을 따른다. 꾸미기 모드에서 손님 통로·입구·작업 접근을 검증한다. 테마 외형은 동일 기능 장비의 외관을 바꾸며, 기능 업그레이드와 별도 표시한다.

## 8. 저장과 실패 복구

레시피 버전, 연구 결과, 영업표, 수락한 주문, 재료 예약, 장비 단계, 개인 배치, 미해결 사건, 고객 경험 집계를 저장한다. 연결이 끊긴 상태에서 고객 경험을 계속 무한 생성하지 않는다. 유예·마감·환불은 [공통 시간 규칙](../01-game/01-core-loop-and-time.md)에 따라 한 번 수행한다.

장비 재배치가 진행 중 주문의 슬롯을 없앨 경우에는 먼저 주문을 안전하게 정리하도록 안내한다. 재접속 시 주문을 다시 수락하지 않고 기존 거래 ID의 결과를 보여준다.
