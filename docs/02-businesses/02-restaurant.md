# 음식점 업종 명세

문서 ID: BIZ-FOOD · 버전: 2.0 · 상태: MVP 구현 기준 · 기준일: 2026-11-11

[문서 트리](../README.md) · [업종 선택](README.md) · [음식점 스토리보드](../03-experience/05-storyboard-restaurant.md)

## 1. 플레이어의 역할

한 가지 메뉴를 믿고 찾을 수 있는 작은 음식점을 운영한다. 손님이 몰리는 시간에 준비량과 대기시간을 맞추고, 재료가 바뀌면 설명과 조리 기준을 함께 바꾼다. 카페보다 준비 공정·재료 활용·예약 이행에 더 큰 비중을 둔다.

대표 제품은 `FOOD_RICE_01` 채소 덮밥이다. 실제 조리법을 가르치는 음식 안전 교재가 아니라, 요구사항 확인·공정 관리·원가·약속 이행을 체험하는 경영 모델이다. 게임에서 완료한 관리 체크를 현실 음식점의 안전 인증처럼 표현하지 않는다.

## 2. MVP 구성

| 항목 | 범위 |
|---|---|
| 메뉴 | 채소 덮밥 1종, 활성 조리 규격 1개 |
| 시작 자산 | 기본 조리대·재료 보관대·판매대·좌석, 80 TC |
| 고객 | 식사 수요 NPC. 가격·양·메뉴 태그·대기시간의 선호를 가짐 |
| 작업 | 준비량 선택, 주문 수락, 공정 순서, 검수, 전달, 예약 조정 |
| 연구 | 조리 표준 / 식재료 활용 |
| 사건 | 재료 대체 요청 / 예약과 처리 지연 |
| 설비 | `EQ_FOOD_1`, `EQ_FOOD_2`, `EQ_FOOD_3` |
| 후속 범위 | 여러 메뉴 동시 생산, 배달 차량, 플레이어 농장 공급망, 직원별 근무표 |

기본 거래는 매출 32 TC, 변동원가 12 TC, 작업 60초이며 이 값은 [경제 원본](../01-game/06-economy-and-items.md)의 균형 가정이다. **20 TC는 거래 공헌이익**이다. 실제 순이익에서는 운영 고정비·연구·사건 대응 비용을 더 뺀다. 원가 예약과 소비는 모든 업종의 동일 규칙을 따른다.

## 3. 주문과 준비 공정

### 영업 전

활성 메뉴, 주문 가능한 수량, 작업 슬롯, 준비 상태, 확정 예약을 표시한다. 예상 수요는 보장 매출로 표시하지 않는다. 플레이어는 준비를 마친 뒤 영업을 시작하거나, 예정 영업 약속을 수정하고 연구를 선택한다.

### 주문 중

| 하위 공정 | 조작 | 확정하는 데이터 |
|---|---|---|
| 요구 확인 | 손님의 메뉴 태그·수량·희망 시간을 확인 | 수락한 제품 버전·약속 조건·운영비 예산 예약 |
| 준비 | 다음 공정에 필요한 자원과 작업 순서 선택 | 예약 자원, 준비 상태 |
| 착수 | 준비된 주문을 생산 슬롯에 배정 | 변동원가 소비, 작업 시작 기록 |
| 조리·검수 | 규격 확인, 원인 경고 대응, 재작업 여부 선택 | 실제 공정 결과와 결함 원인 |
| 전달 | `IN_PROGRESS`의 마지막 전달 행동 | 조건 충족 후 `READY`를 거쳐 자동 `DELIVERED`, 한 번의 정산과 고객 경험 |

착수 전 취소는 예약한 변동원가를 해제한다. 착수 후 귀책 취소는 이미 사용한 원가를 되돌리지 않는다. 서버 원인으로 실패한 거래는 공통 복구 규칙에 따라 원가를 복구한다. NPC가 테이블로 이동하는 화면 연출은 결제 확정 조건이 아니다.

### 준비와 낭비

MVP의 기본 변동원가는 주문 착수 때 소비한다. 별도의 무료 무한 재고나 자동 상한 없는 선조리 수량을 만들지 않는다. 사건·연구에서 만든 시험 배치가 폐기되면 그 시도의 비용 기록에만 반영한다. 품질이 나쁜 주문을 취소한 손실과, 팔리지 않은 물량을 사전에 대량 생산한 손실을 혼용하지 않는다. 대량 선조리 재고는 후속 시스템으로 분리한다.

## 4. 품질과 연구

음식점의 품질 근거는 규격 검증, 공정 일관성, 재료 조건, 검수 상태다. 손님의 양·맛·식사 목적 선호는 시장 적합성으로 기록한다. 오래 유지한 메뉴도 안정적인 수요가 있을 수 있으며, 연구를 하지 않았다는 이유만으로 자동 부패시키지 않는다.

| 연구 | 수행 | 완료 증거 | 전략 |
|---|---|---|---|
| `RND_FOOD_STANDARD` 조리 표준 | 원인 경고가 있는 공정을 고치고 같은 조건으로 비교 | 편차·결함의 전후 차이 | 안정된 반복 제공 |
| `RND_FOOD_YIELD` 식재료 활용 | 허용된 배합을 비교하고 손님 요구와 원가를 함께 검토 | 요구 태그 유지, 비용·결과 비교 | 현재 고객층에 맞는 메뉴 규격 |

각 연구는 단계당 20 TC, 활동 90초를 사용하며 생산 슬롯을 공유한다. 최대 3단계, 선행 사업 레벨 1·2·3이다. 정확한 적용 효과와 수치 상한은 [운영과 연구](../01-game/03-operations-quality-rnd.md)를 따른다. ‘식재료 활용’ 연구만으로 원가를 임의 할인하지 않으며, 명세에서 승인한 품질·적합성 개선만 적용한다.

연구는 기존 주문을 정리하고 `CLOSED`에서만 시작·진행한다. 연구하는 동안 신규 주문을 수락하지 않는다. 공개한 미래 영업 약속과 충돌하는지 시작 전에 검사하며, 정상적으로 공지한 연구 휴업 자체에는 명성 벌점이 없다. 고객에게 보인 기한을 임의로 바꾸지 않는다.

## 5. 선택 사건

### EV_FOOD_01 재료를 바꿔도 될까

조건: 준비된 재료의 특성이 활성 조리 규격과 맞지 않거나, 공지한 메뉴 태그를 유지할 수 있는지 확인이 필요한 경우. 실제 식품 위해를 묘사하기보다 게임의 재료 태그와 품질 지표를 사용한다.

NPC 대사: “다른 재료는 준비할 수 있어요. 지금 메뉴와 같은 조건으로 제공할 수 있는지 먼저 확인해 주세요.”

| 선택 | 즉시 효과 | 지연 결과 |
|---|---|---|
| A. 규격 확인 후 대체 | 시험 비용·시간, 신규 수락량 제한 | 검증된 새 버전으로 이후 주문 제공 |
| B. 기존 메뉴 유지, 해당 수량 제한 | 대체 재료를 사용하지 않음 | 매출 기회 일부를 포기하고 기존 약속 유지 |
| C. 다른 메뉴 태그로 제안 | 동의한 신규 고객에게만 변경 조건 제시 | 변경 조건을 받아들인 고객의 경험으로 평가 |

이미 수락한 메뉴를 고객 동의 없이 변경하는 선택은 제공하지 않는다. C는 새로운 제품 ID를 생성하는 것이 아니라 동일 대표 제품의 명시된 규격 버전으로 처리한다. 동의를 얻지 못하면 수락 전 단계에서 종료하거나 정해진 취소 규칙을 따른다.

### EV_FOOD_02 예약 시간과 조리 지연

조건: 확정 예약의 남은 시간보다 현재 작업량이 커지고, 동일 주문의 지연 사건이 열려 있지 않은 경우.

| 선택 | 새로 합의하는 것 | 결과 |
|---|---|---|
| A. 예상 시간을 알리고 변경 요청 | 새 수령 시각 | 동의 후 새 기한으로 평가, 동의 전 기존 기한 유지 |
| B. 기존 주문의 순서 변경 합의 | 영향을 받는 고객의 순서와 기한 | 동의한 기한 버전으로 순서를 조정, 개별 주문은 각각 완수 후 정산 |
| C. 해당 예약을 취소하고 정리 | 취소 사유와 이미 발생한 원가 | 매출 기회 상실·귀책 결과, 다른 주문의 추가 지연 방지 |

NPC가 연장에 동의한다는 보장은 없다. 동의·거절은 고객의 고정된 허용 조건으로 판단하고, 재접속하여 다시 추첨하지 않는다. 미리 밝힌 요구를 지키지 못한 사실과 이후의 성실한 회복 행동을 별도 기록한다.

### 사건 비용과 시간

| 사건·선택 | 추가 직접비 | 추가 시간 | 추가 운영비 예산 | 효과 |
|---|---:|---|---:|---|
| EV_FOOD_01 A | 2 TC | 검증 작업 30초 | 1 TC | 검증된 새 규격을 이후 주문에 적용 |
| EV_FOOD_01 B | 0 TC | 0초 | 0 TC | 기존 규격과 가능한 수량 유지 |
| EV_FOOD_01 C | 0 TC | 0초 | 추가 고정분 없음 | 동의한 주문만 변경 태그로 기본 정산 |
| EV_FOOD_02 A | 0 TC | 동의한 기한 연장 30초, 생산 작업 추가 없음 | 최대 1 TC 추가 예약 | 고객이 동의한 기한 버전으로 평가 |
| EV_FOOD_02 B | 0 TC | 생산 작업 추가 없음 | 기존 작업의 필요 예산 유지 | 영향 고객의 동의한 순서·기한 버전 적용 |
| EV_FOOD_02 C | 0 TC | 추가 없음 | 새 예약 없음 | 착수 전 예약 해제, 착수 후 귀책 원가 손실 |

추가 운영비 예산은 실제 유상 운영 시간에 따라 소비하며 사용하지 않은 잔여는 해제한다. 검사 직접비 2 TC는 착수 때만 소비한다. 검사는 공유 슬롯의 `EVENT_WORK`이고 연구 단계·XP가 오르지 않는다. 예산이 없으면 시간 연장 없는 대안을 제공한다. 예약 순서를 바꾸어도 동의하지 않은 고객의 기한을 초기화하지 않는다. 수치의 권위는 [경제 원본](../01-game/06-economy-and-items.md)에 있다.

## 6. 설비와 배치

| 단계 | 설비 | 비용·선행 조건 | 운영 기능 |
|---|---|---|---|
| T1 | `EQ_FOOD_1` 기본 조리 설비 | 시작 지급 | 기본 공정과 검수 |
| T2 | `EQ_FOOD_2` 표준 조리 설비 | 120 TC, 사업 레벨 2 | 원인 파악과 규격 확인 지원 |
| T3 | `EQ_FOOD_3` 정밀 조리 설비 | 300 TC, 사업 레벨 3 | 높은 수준의 검수·품질 실현 |

설비만 구매해도 주문 슬롯이 늘거나 기본 작업 시간이 줄어들지는 않는다. 도구가 지원하는 품질 상한과 실제 달성 품질을 분리한다. 좋은 도구를 사도 공정 경고를 방치하면 그 결과가 남는다.

좌석·판매대·작업 공간은 검증된 통로를 유지해야 한다. 손님이 보기 좋은 장식과 기능 동선은 함께 설계하되, DG 테마 자체에 수요 가중치를 주지 않는다.

## 7. 경쟁과 회복

경쟁 상대는 같은 식사 필요를 충족하는 업체다. 메뉴 태그가 맞지 않는 손님을 가격만 낮춰 강제로 유치하지 않는다. 낮은 품질로 손님이 줄었을 때는 최근 주문 원인, 취소·지연 원인, 수요 이탈 이유를 보여준다.

회복 순서는 현재 약속 정리 → 원인 수정 → 제한된 정상 주문 → 실제 경험 축적이다. 명성 복구를 현금 아이템으로 구매하지 않는다. 정상 마감 후 오프라인인 동안에는 재료 상태와 명성을 연속으로 훼손하지 않는다.
