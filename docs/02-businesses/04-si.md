# SI 회사 업종 명세

문서 ID: BIZ-SI · 버전: 2.0 · 상태: MVP 구현 기준 · 기준일: 2026-11-11

[문서 트리](../README.md) · [업종 선택](README.md) · [SI 스토리보드](../03-experience/07-storyboard-si.md)

## 1. 플레이어의 역할

고객사의 업무를 이해하고 요구사항에 맞게 시스템을 구성하는 SI 회사를 운영한다. 같은 제품을 다수에게 판매하는 소프트웨어 업종과 달리, **한 고객과 합의한 범위·납기·검수 기준을 끝까지 이행하는 것**이 중심이다.

대표 프로젝트는 `SI_RESERVATION_01` 맞춤 예약 연동이다. NPC 가게의 예약 정보를 내부 일정판과 연결하는 게임상 과제이며, 현실의 계정 정보·개인정보·외부 시스템을 다루지 않는다. 구현은 블록 선택과 의존 관계, 요구 카드, 테스트 증거로 표현한다.

## 2. MVP 구성

| 항목 | 범위 |
|---|---|
| 프로젝트 | 맞춤 예약 연동 1종, 고객 조건으로 수락 범위가 달라짐 |
| 시작 자산 | 상담 테이블·요구 보드·시험 환경·기본 템플릿, 80 TC |
| 고객 | 맞춤 구축 수요 NPC. 기능 적합성·약속 신뢰·납기·예산을 비교 |
| 핵심 행동 | 요구 확인, 범위 합의, 견적 확인, 작업 순서, 중간 검토, 최종 검수 |
| 연구 | 요구 검증 / 통합 테스트 |
| 사건 | 추가 기능 요청 / 통합 검수 불일치 |
| 설비 | `EQ_SI_1`, `EQ_SI_2`, `EQ_SI_3` |
| 후속 | 선금·분할금, 대출, 다수 계약 병렬 수행, 플레이어 업체 간 외주·계약 |

기본 거래는 총 매출 64 TC, 변동원가 24 TC, 작업 120초다. 40 TC는 공헌이익이며 운영 고정비·연구·재작업 비용을 반영한 최종 순이익이 아니다. **중간 검수에서는 현금을 지급하지 않고, 최종 검수 완료 때 총액을 한 번 지급한다.** 금액 64 TC는 기본 가격 예시다. 실제로 조정한 가격을 수락했다면 `P = acceptedPriceTC`를 끝까지 사용하며, 사건을 선택해도 총액을 64 TC로 다시 설정하지 않는다.

## 3. 계약을 명확하게 만든다

계약 카드에는 반드시 다음을 노출한다.

- 고객이 해결하려는 업무 문제.
- 이번에 제공할 기능과 이번 범위에 포함하지 않은 기능.
- 최종 검수가 통과할 조건.
- 약속된 완료 시점과 중간 확인 지점.
- 총액, 착수 원가, 추가 비용이 필요한 경우의 동의 절차.
- 변경 요청이 합의되기 전까지는 기존 계약이 유지된다는 설명.

견적 화면의 금액은 승인된 경제 설정에서 제공한다. 가격을 낮추기 위해 검수 조건을 몰래 삭제할 수 없다. 한 번 수락한 계약의 버전은 저장하며, 요구 보드의 이후 수정으로 기존 계약을 덮어쓰지 않는다.

## 4. 프로젝트 흐름

| 공정 | 플레이어 행동 | 검증·정산 |
|---|---|---|
| 상담 | NPC 요구를 듣고 모호한 항목 질문 | 요구 확인 상태, 상담 자체는 매출 없음 |
| 범위 합의 | 포함·제외 기능과 검수 기준 확인 | 계약 버전 확정, 원가·운영비 예산 예약 |
| 착수 | 작업 계획을 슬롯에 배정 | 변동원가 소비, 작업 시작 기록 |
| 구성 | 의존 조건에 맞게 작업 카드를 완료 | 작업 증거와 구성 버전 |
| 중간 검토 | 고객이 이해한 요구와 현재 결과 비교 | 불일치 발견·변경 요청, 현금 지급 없음 |
| 통합 검수 | 연결 조건과 핵심 흐름 확인 | 최종 통과 증거 또는 재작업 원인 |
| 인수·완료 | 고객 동의와 납품 상태 확인 | 총액 매출, 고객 경험, 완료 기록 한 번 |

연구와 고객 작업은 하나의 생산 슬롯을 공유한다. MVP 연구는 기존 계약을 정리한 `CLOSED` 상태에서만 시작·진행한다. 계획 단계에서 연구 시간과 다음 확정 영업 약속을 비교한다. 이미 수락한 계약의 납기를 연구 선택으로 자동 연장하지 않는다.

## 5. 품질과 연구

SI의 실제 품질은 합의된 요구의 충족, 구성의 일관성, 통합 검수 증거, 미해결 결함으로 판단한다. 특정 고객에게 맞춘 기능이 다른 고객에게도 가치가 있을 것이라고 자동 판단하지 않는다. 시장 적합성은 수주 후보가 요구하는 기능과 현재 수행 능력을 비교한다.

| 연구 ID | 수행 | 얻는 능력 |
|---|---|---|
| `RND_SI_REQUIREMENTS` | 모호한 요구를 질문하고 검수 가능한 문장으로 바꾸는 연습 | 합의된 요구 누락·오해를 발견할 근거 |
| `RND_SI_INTEGRATION` | 구성 요소별 결과와 연결 결과를 비교 | 개별 성공과 전체 성공의 차이를 확인 |

각 연구 단계는 20 TC와 활동 90초, 공유 슬롯을 사용한다. 최대 3단계이며 선행 사업 레벨 1·2·3이다. 실제 수치 효과와 상한은 [운영과 연구](../01-game/03-operations-quality-rnd.md)가 소유한다. 연구가 높아도 합의하지 않은 일을 대신 수락하거나 고객의 동의를 생략하지 않는다.

## 6. 선택 사건

### EV_SI_01 이것도 같이 해 주세요

조건: 현재 계약에 없는 추가 기능을 고객이 요청하고, 해당 계약에 미해결 변경 요청이 없는 경우. NPC 대사: “일정판 말고 직원 알림도 되면 좋겠어요. 이번 작업에 넣을 수 있나요?”

| 선택 | 합의 내용 | 뒤에 발생하는 결과 |
|---|---|---|
| A. 같은 총액으로 범위와 일정 변경 | 추가 요구와 작업 30초를 제시, 추가 운영비 1 TC 예산 확보 | 고객 동의 후 새 계약 버전, 후속 문의를 처리할 시간이 줄어들 수 있음 |
| B. 기존 기능과 교체 제안 | 총 범위 안에서 우선순위 변경 | 빠지는 기능과 새 검수 조건을 모두 확인 |
| C. 현재 계약을 먼저 완료 | 추가 요청을 이번 범위에 넣지 않음 | 현재 약속 이행, 다음 기회로 별도 기록 |

MVP는 수락 총액 P(기본 가격 64 TC)와 기본 변동원가 24 TC를 유지한다. A만 작업 시간이 30초 늘고 추가 변동원가는 0 TC다. B는 같은 작업량 안에서 동의한 기능을 교체하고 C는 원래 범위를 유지한다. A는 추가 운영비 예산 1 TC를 확보할 수 있을 때만 선택한다. C를 골라도 기존 계약의 필수 조건은 모두 충족해야 한다. 상대가 요청했다고 바로 계약 조건이 바뀌지 않으며, 즉석 견적·분할금은 후속 범위다.

### EV_SI_02 각각 되는데 함께는 안 된다

조건: 각 구성 요소의 검증은 통과했으나 최종 연결 조건 하나가 실패한 경우. 실패한 조건과 영향 범위를 플레이어에게 공개한다.

| 선택 | 대응 | 완료 조건 |
|---|---|---|
| A. 원인 수정 후 재검수 | 재작업 30초, 추가 운영비 예산 1 TC와 시간 변경 동의 | 기존 최종 검수 조건 통과 |
| B. 대체 구성에 합의 | 다른 구현으로 동일 필수 조건 충족, 작업 30초·추가 운영비 예산 1 TC | 고객 동의한 구성으로 필수 검수 조건 통과 |
| C. 진행을 중단하고 계약 정리 | 귀책과 비용을 확인하고 미완료 종료 | 매출 없음, 사용한 원가·관계 결과 한 번 반영 |

A·B의 추가 변동원가는 0 TC이고 총액은 수락 당시 P다. 실제 추가 운영 시간의 고정비가 별도로 소비된다. B는 필수 조건을 삭제하거나 실패 항목을 숨기는 버튼이 아니다. 동일한 필수 결과를 얻는 다른 구성에 고객이 동의해야 한다. 추가 운영비 예산이 없으면 A·B를 비활성화하고 C의 명시적 종료를 제공한다. C는 최종 매출이 없고 이미 사용한 기본 원가 24 TC를 한 번의 손실로 남긴다.

### 사건 수치와 수락 제한

| 사건·선택 | 계약 총액 | 추가 직접비 | 추가 작업 | 추가 운영비 예산 |
|---|---:|---:|---:|---:|
| EV_SI_01 A | 수락 총액 P 유지 | 0 TC | 30초 | 1 TC |
| EV_SI_01 B·C | 수락 총액 P 유지 | 0 TC | 0초 | 추가 없음 |
| EV_SI_02 A·B | 수락 총액 P 유지 | 0 TC | 30초 | 1 TC |
| EV_SI_02 C | 완료 매출 없음 | 새 직접비 없음 | 0초 | 새 예약 없음 |

기본 변동원가 24 TC는 모든 경로에서 같은 착수 규칙을 따른다. C 취소 시 착수한 원가는 이미 발생한 손실로 남으며 추가 24 TC를 다시 차감하지 않는다. 30초 추가 대응은 공유 슬롯의 `EVENT_WORK`이며 해당 사건·계약에 연결해 한 번 수행한다. 추가 운영비 예산을 확보할 수 없으면 시간을 늘리는 선택은 비활성화한다. 다음 문의 기회 상실과 추가 운영비 때문에 무료 범위 추가가 항상 유리하지 않다. 수치의 권위는 [경제 원본](../01-game/06-economy-and-items.md)에 있다.

## 7. 설비와 공간

| 단계 | 설비 | 비용·선행 | 역할 |
|---|---|---|---|
| T1 | `EQ_SI_1` 기본 통합 작업대 | 시작 지급 | 요구와 작업 연결 |
| T2 | `EQ_SI_2` 검증 통합 작업대 | 120 TC, 레벨 2 | 요구 누락·불일치 확인 |
| T3 | `EQ_SI_3` 정밀 통합 작업대 | 300 TC, 레벨 3 | 높은 품질 상한의 통합 검증 지원 |

슬롯과 기본 작업 시간은 자동으로 늘거나 줄지 않는다. 설비의 표현은 도구의 정밀함과 검수 가능 범위로 보여준다. 회사의 프로젝트 기념판에는 고객이 동의한 결과와 플레이어의 역할을 남기며, 모든 성공을 동일한 금색 트로피로 만들지 않는다.

## 8. 실패와 회복

잘못된 요구 확인은 실제로 재작업·지연·수주 경쟁력에 영향을 준다. 결과 화면은 ‘능력 부족’처럼 사람을 평가하지 않고 **확인하지 않은 요구, 합의되지 않은 변경, 미통과 검수**를 지목한다. 다음 계약에서 같은 종류의 요구를 확인하면 개선을 관찰할 수 있다.

정상 마감은 새 문의를 막고 기존 계약을 이행·합의된 종료로 정리하는 절차다. 영업 종료 버튼이 확정 계약의 기한이나 원가를 삭제하지 않는다. 연결 끊김은 공통 유예와 마감 규칙을 사용하며, 같은 계약을 반복 생성해 첫 보상을 얻지 못한다.
