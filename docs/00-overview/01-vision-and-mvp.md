# 게임 비전과 MVP 범위

[전체 문서 트리](../README.md) · [상위 분야](README.md)

> 문서 ID: OV-01 · 버전: 2.0 · 기준일: 2026-11-11 · 상태: 구현 전 제작 기준안

## 한 문장 정의

오픈타운은 같은 상권의 여러 창업자가 고객의 선택을 두고 경쟁하며, 운영·연구·공간·평판을 발전시키는 실시간 창업 타이쿤이다. 카페, 음식점, 소프트웨어 제품 회사, SI 회사를 선택해 자신만의 사업과 공간을 만든다.

이 문서는 제품의 기준이다. 세부 수치의 원본은 [경제와 아이템](../01-game/06-economy-and-items.md), 상태와 명령의 원본은 [공통 구현 명세](../04-implementation/01-engine-neutral-spec.md)다. 실제 게임이 구현되었거나 재미·매출·학습 효과가 확인되었다는 의미는 아니다.

## 플레이어에게 약속하는 경험

1. 선택한 업종에 따라 일하는 방식과 고민이 달라진다.
2. 내 공간과 브랜드에 취향과 성과가 쌓인다.
3. 손님은 가격, 품질, 적합성, 대기, 신뢰를 비교한다.
4. 열겠다고 한 시간에 열지 않거나 납품 약속을 어기면 실제 결과가 생긴다.
5. 실패의 이유를 알아보고 고칠 수 있다. 다른 플레이어가 잘하는 이유도 관찰할 수 있다.
6. 선택한 해결책은 기록되며 뒤의 사건과 고객 반응에 영향을 준다.

경쟁의 감정은 ‘저 가게처럼 나도 해보고 싶다’에서 시작한다. 성공한 외관을 복제하면 같은 성과가 나는 것이 아니라, 자신의 고객과 운영 방식에 맞는 전략을 세워야 한다.

## 대상과 플레이 환경

초기 대상은 13세 이상 청소년과 성인으로 가정한다. 실제 공개 연령·출시 국가·인증 및 결제 조건은 출시 결정 사항이다. PC 브라우저의 마우스·키보드를 첫 기준으로 하고 터치 조작을 같은 행동 집합으로 설계한다. 특정 플랫폼에서의 접근 가능성은 별도 플랫폼 문서에서 검토한다.

한 스테이지에는 실제 플레이어가 최대 6명 참여한다. 4개 업종을 자유롭게 고르고 동일 업종 중복을 허용한다. 고객은 수요 종류에 맞는 사업을 비교하므로, 카페의 판매량과 SI의 계약 건수를 그대로 순위화하지 않는다.

## 공개 MVP에 포함하는 것

| 영역 | 공개 MVP 완료 범위 | 완료 확인 |
|---|---|---|
| 창업 선택 | 카페·음식점·소프트웨어·SI 모두 선택 가능 | 4개 업종으로 최초 거래를 각각 완료 |
| 사업 소유 | 계정당 활성 사업 1개와 개인 공간 1개 | 이중 접속으로 동시 생산 불가 |
| 실시간 스테이지 | 최대 6명, 입장·퇴장·재접속, 고객 공유 | 동일 고객의 중복 계약·중복 결제 없음 |
| 업종별 깊이 | 대표 제품 1개, 연구 2갈래, 핵심 사건 2개, 설비 3단계 | 업종마다 다른 작업과 선택 결과 |
| 경영 | 개점·마감·예고 영업·원가·운영비·연구·품질 | 방치 원인과 개선 결과를 설명 가능 |
| 경쟁 | 카테고리별 한정 수요, 외부 업체 또는 구매 포기 | 고객 수와 수요 처리량 보존 |
| 선택형 이야기 | 공통 도입과 업종별 10컷, 후속 결과·분기 회고 | 재접속으로 선택 결과 변경 불가 |
| AI 사건 | 규칙 기반 감독과 허용 사건 집합 | 모델이 없어도 모든 핵심 흐름 진행 |
| 꾸미기 | 기본 기능 가구·외형·간판·기념품·배치 | 기능 배치와 외형 효과 구분 |
| 경제 | TC·DG·PB·XP, 구매 및 보상 중복 방지 | 지갑·보유·원장 불변식 통과 |
| 소셜 | 공간 방문, 지정 문구와 행동 요청, 비교 보고 | 방문 수나 좋아요로 재화 생성 없음 |
| 운영 | 진단·기능 플래그·복구·결제 대응 | 장애 원인별 재현과 복구 가능 |

## 개발 단계와 공개 범위의 차이

내부 첫 완성 구간은 카페 한 업종이다. 이 단계에서 고객 경쟁, 비용, 품질, 선택 사건, 저장, 재접속을 끝까지 연결한다. 이후 같은 공통 시스템에 음식점·소프트웨어·SI의 콘텐츠와 작업 흐름을 붙인다. 카페만 완성된 빌드는 내부 검증본이며, 4개 업종 선택을 약속한 공개 MVP 완료로 부르지 않는다.

## 후속 범위

사업 여러 개 동시 경영, 영구 업종 전환, 플레이어 간 하도급과 자금 거래, 주식·대출·세금 시뮬레이션, 직원 인사 관리, 자유 업로드 아이템, 사용자가 쓰는 실제 소스 코드, 영구 공유 도시 편집은 후속이다. SI의 중간 검수는 MVP에도 존재하지만 분할 대금·선금은 후속이다.

시제품에서 필요한 임시 개발용 거래와 운영자 명령은 게임 기능이나 유료 상품으로 노출하지 않는다.

## 성장과 재방문의 이유

초기에는 한 고객의 요구를 이해하고 정상적으로 마감하는 데 집중한다. 다음에는 연구와 공정 개선으로 결과를 바꾸고, 이후에는 같은 고객군을 겨냥한 경쟁자의 강점을 분석한다. 성장의 전시는 가게 규모, 선택한 테마, 고유 간판, 연구로 완성한 제품의 설명, 실제 플레이로 획득한 기념품이 담당한다.

매일 접속 보상이나 오프라인 손실 복구를 재방문의 중심으로 삼지 않는다. 세션을 마칠 때 ‘다음에 개선할 한 가지’와 ‘그 개선으로 달라질 고객’을 보여 준다.

## 출시를 결정할 증거

- 신규 이용자가 도움 없이 업종을 선택하고 최초 거래와 정상 마감을 수행한다.
- 손님이 줄어든 이유를 최소 하나 설명하고, 의미 있는 조치를 선택한다.
- 동일 상황에 여러 전략이 생기며 최저가 또는 단일 연구가 항상 우세하지 않다.
- 6명 동시 접속과 재접속에서 고객·TC·아이템 소유권이 일치한다.
- 결제, 저장, 장애, 강제 마감의 검증을 통과한다.

매출·재방문·학습 수치의 합격선은 초기 테스트의 기준분포를 보고 확정한다. 아직 관측되지 않은 성공률을 성과로 기재하지 않는다.
