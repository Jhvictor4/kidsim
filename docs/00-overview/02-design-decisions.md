# 설계 결정과 이전 버전 변경

## 이번 버전의 권위

v2는 기존 오픈타운의 소유·꾸미기·교육·재화 구상을 계승하고, 최신 요청에 따라 경쟁과 창업 운영을 중심으로 다시 정의한다. v1의 파일은 보존한다. 문서 내용이 충돌하면 이 v2 패키지의 해당 분야 원본을 적용한다.

| 결정 ID | v2 결정 | 이유와 구현 영향 |
|---|---|---|
| D01 | 실시간 6인 스테이지와 업종별 고객 경쟁 | 한 장소에 함께 있는 의미를 고객 선택과 운영 결과로 연결 |
| D02 | 공개 MVP에 4개 업종 포함 | 창업 유형 선택 자체가 제품의 핵심 약속 |
| D03 | 공통 게임 규칙과 플랫폼 구현 분리 | 게임의 상태·경제·테스트를 다른 런타임에도 이식 |
| D04 | 웹 구현을 첫 배포 대상으로 지정 | 렌더링·네트워크·저장·결제의 책임을 따로 정의 |
| D05 | TC·DG·PB·XP 유지 | 플레이 자금·유료 표현·의뢰 예산·성장 의미 유지 |
| D06 | 실화폐 결제는 플랫폼 어댑터에서 처리 | DG 정의에 특정 플랫폼 통화를 넣지 않음 |
| D07 | 정상 마감 후 미접속 감쇠 중단 | 현실의 선택·약속·비용을 압축하되 상시 접속 요구 방지 |
| D08 | ‘공표한 영업’과 ‘단순히 닫힘’ 구분 | 쉬면서 연구하는 전략과 약속을 어기는 행동의 차이 표현 |
| D09 | 품질·시장 적합성·신선함 분리 | 오래된 메뉴가 시간만으로 맛없어지는 인과 오류 방지 |
| D10 | 규칙 기반 AI가 기준 동작 | 재현 가능한 사건, 비용 통제, 모델 없이 작동하는 핵심 게임 |
| D11 | 모델의 출력은 검증 전 제안 | 지갑·명성·확정 보상에 모델의 직접 권한을 주지 않음 |
| D12 | 선택을 영구 기록하고 결과 회고 제공 | 재접속 재추첨을 막고 선택과 결과의 관계를 드러냄 |
| D13 | 카테고리별 수요와 외부 선택지 | 업종이 다른 상품을 무리하게 한 시장 점수로 비교하지 않음 |
| D14 | 착수 원가와 영업 고정비 분리 | 매출이 곧 이익이라는 오해를 줄이고 가동률을 학습 |
| D15 | DG는 외형과 프리셋 | 유료 품질·명성·수요·연구 시간 보너스 배제 |
| D16 | 계정당 하나의 활성 사업 | 동시 사업·다중 접속·복잡한 계정 간 경제를 초기 범위에서 제거 |

## 현실성을 반영하는 경계

실제 창업에서 관찰할 수 있는 ‘수요에 맞지 않는 상품’, ‘품질 관리 부족’, ‘과도한 약속’, ‘대기와 납기’, ‘원가와 고정비’, ‘반복 개선’을 게임의 원인과 결과로 표현한다. 세금, 법적 책임, 금융상품, 실제 사업 수익을 정확하게 예측하는 도구로 만들지는 않는다.

실제 맛은 사람이 느끼는 것이므로 게임에서는 공정 정확도·재료 상태·고객 취향 적합성의 관측값으로 표현한다. 소프트웨어 역시 실제 코드 품질 대신 요구 충족·검증 범위·결함 상태·지원 대응으로 구성한다. UI는 이러한 단순화를 설명한다.

## 정상 휴식과 책임 회피

정상 마감은 새로운 고객을 받지 않고 진행 중인 일을 처리한 뒤 떠나는 행동이다. 이 경우 미접속 시간에 고정비나 품질 감쇠가 계속되지 않는다. 이미 확정된 선택·완료 결과·미이행 기록은 남는다.

연결 끊김에는 60초 복귀 유예가 있고, 유예 중 새 고객을 받지 않으며 진행·비용·기한이 동결된다. 유예 종료 시 확정된 작업과 약속만 한 번 정산한다. 서버 전체 장애는 이용자의 태만으로 평가하지 않는다. 반복 재접속으로 사건 선택이나 사용한 원가가 사라지지 않는다.

## 남은 제품 결정

| 결정할 것 | 현재 가정 | 결정 시점 |
|---|---|---|
| 실제 공개 연령·국가 | 13세 이상, 한국어 우선 | 외부 테스트 모집 전 |
| 결제 사업자·상품 가격 | 제공자 추상화, 최종 단가 미확정 | 결제 활성화 전 |
| 기준 PC·휴대기기 | 저사양 노트북과 중급 휴대기기 범주 | 성능 기준 장비 선정 시 |
| 스테이지 공개 방식 | 초대 또는 자동 매칭 | 친구 테스트 후 |
| 경쟁 균형 수치 | 문서의 초기 수요·가중치·비용 | 반복 플레이테스트 후 |
| 경량 모델 사용 여부 | 없어도 출시 가능 | 규칙 기반 사건이 검증된 후 |

미결정 항목 때문에 공통 게임 코어 개발을 멈추지 않는다. 외부 결제 상품은 샌드박스 상태로, 모델은 정적 문장 대체로 개발할 수 있다.

## 변경 절차

규칙 변경은 관련 문서 ID·설정 키·테스트 ID·저장 스키마 영향을 함께 기록한다. 이미 수락한 주문과 계약은 수락 당시 콘텐츠 버전을 유지한다. 진행 중 사건의 선택지와 비용을 조용히 교체하지 않는다. 경제 변경 전후의 동일 seed 실험으로 차이를 확인한다.
