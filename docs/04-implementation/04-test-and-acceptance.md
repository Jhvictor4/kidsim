# 검증 명세와 인수 기준

[전체 문서 트리](../README.md) · [상위 분야](README.md)

> 문서 ID: QA-01 · 버전: 2.0 · 기준일: 2026-11-11 · 상태: 구현 전 제작 기준안

## 검증 상태

이 문서는 구현 후 수행할 테스트 명세다. 게임 빌드·결제·실기기 성능·학습 효과는 아직 검증하지 않았다. 문서 링크와 내부 정의의 일치 여부를 확인하는 작업은 실제 게임 테스트와 별도로 기록한다.

모든 테스트 결과에는 빌드·콘텐츠 버전, seed, 초기 상태, 명령 ID, 기대 상태, 실제 원장과 재현 로그를 남긴다. 화면 스크린샷만으로 경제 처리의 성공을 판정하지 않는다.

## 공통 불변식

1. 같은 수요 토큰은 최대 한 사업의 확정 거래가 된다.
2. TC·DG 지갑은 허용 범위 밖이 되지 않으며 예약 합계가 보유액을 넘지 않는다.
3. 한 거래의 재료 예약·원가 소모·매출은 각각 허용된 시점에 한 번 발생한다.
4. 운영비는 유상 운영 시간에서만 누적하며 마감·재접속으로 누적 잔여를 지우지 않는다.
5. 결정된 선택과 지연 효과는 재접속·응답 유실로 반복 또는 변경되지 않는다.
6. 외형·DG 지출·좋아요는 고객 효용이나 품질·명성의 성능 입력이 아니다.
7. 서버 장애와 사용자 약속 불이행은 다른 원인 코드다.
8. 콘텐츠 버전이 바뀌어도 기존 거래는 수락한 정의로 재현된다.

## 경쟁과 경제 실험

고정 seed 묶음에서 가격만 바꾸기, 품질만 바꾸기, 유지보수만 생략하기, 명성만 바꾸기, 모든 사업의 정책이 같은 경우를 비교한다. 각 실험은 한 변수를 바꿔 원인을 읽을 수 있게 한다. 순위뿐 아니라 외부로 빠진 수요, 가동률, 순이익, 대기, 이탈 사유를 기록한다.

초기 수요와 가격에서 특정 업종이 항상 유리하다면 실제 고객의 차이와 균형용 수치의 원인을 분리해 검토한다. 거래 건수와 금액이 다른 업종을 단일 총매출 순위로 균형 판정하지 않는다.

재기지원은 ‘손실 생성→회복→다른 보상 취득’의 반복으로 순자산이 늘어나는지 확인한다. 초기 지급·연습·PB·리서치 철회·유료 외형·반복 사건을 조합한 순환도 검사한다.

## 장애 실험

- 고객 예약 확정 직전과 직후에 연결을 끊는다.
- 비용 확정 후 화면 응답을 잃게 한다.
- 저장 확정 후 알림 전 서버를 중단한다.
- 이전 권위 세대의 요청과 새 서버의 요청을 동시에 보낸다.
- 외부 결제 완료·환불 이벤트의 순서를 바꾸고 중복 전달한다.
- 고객 수요가 몰리는 시점에 처리 지연을 발생시킨다.

원장과 권위 상태를 기준으로 판정하고, 장애로 기한이 지나간 것을 사용자 귀책으로 기록하지 않는다.

## 출시 관문

핵심 불변식 위반은 출시 차단이다. 4업종의 정상 완료·정상 마감·실패 회복과 6인 경쟁을 모두 확인한다. 기준 기기 성능과 플랫폼별 결제·정보 처리 조건도 충족해야 한다. 경미한 연출 문제는 별도 목록으로 관리하되 거래나 선택의 의미를 가리는 UI 문제는 경미한 것으로 분류하지 않는다.
