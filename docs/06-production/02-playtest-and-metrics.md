# 플레이테스트와 교육 효과 평가

[전체 문서 트리](../README.md) · [상위 분야](README.md)

> 문서 ID: PROD-02 · 버전: 2.0 · 기준일: 2026-11-11 · 상태: 구현 전 제작 기준안

## 평가 목적

플레이어가 자기 사업을 만들고 싶어 하는지, 고객을 놓친 이유를 이해하는지, 선택의 대가를 감당하며 개선하는지 확인한다. 재방문과 결제 의향은 별도 관측이며, 교육 효과를 입증하는 지표로 대신 사용하지 않는다.

본 문서는 연구 결과가 아니라 검증 계획이다. 정해진 선택지를 기억하는 것과 낯선 창업 상황에 원리를 적용하는 것을 구분한다.

## 테스트 순서

### 1차 조작과 개념 이해

처음 보는 참여자가 설명 없이 업종을 고르고, 첫 거래를 처리하고, 보고서를 읽고, 정상 마감하는지 관찰한다. 진행자가 막힌 곳을 바로 설명하기보다 화면에서 무엇을 기대했는지 기록한다. 4개 업종별로 관측 사례를 확보한다.

### 2차 경쟁과 전략

동일한 성장 구간의 참여자를 같은 스테이지에 넣는다. 가격, 연구, 품질 관리, 영업 계획이 다른 전략으로 이어지는지 본다. 손님이 줄어든 사용자가 곧바로 ‘돈을 안 써서’ 또는 ‘운이 나빠서’라고만 생각한다면 원인 정보와 시장 설계를 수정한다.

### 3차 선택과 복구

한 번은 무난한 상황, 한 번은 품질 또는 약속 문제가 있는 상황을 제공한다. 비용이 드는 대응과 시간이 드는 대응의 차이를 이해하는지, 실패 후에도 계속 시도할 수 있는지 확인한다. 재접속과 서버 장애도 별도 시나리오로 경험하게 한다.

### 4차 학습 전이

게임에서 보지 않은 요구 조건·원가·작업 시간을 가진 짧은 사례를 제시한다. 예산만 비교하는지, 시간과 약속·품질·고객 적합성을 함께 고려하는지 관찰한다. 정답 하나를 고르는 것뿐 아니라 선택 이유를 설명하도록 한다.

## 측정 항목

| 질문 | 관측 지표 | 해석의 한계 |
|---|---|---|
| 시작할 수 있는가 | 업종확정·최초거래·마감완료, 도움요청지점 | 빠른완료가항상좋은이해는아님 |
| 내것이라고 느끼는가 | 간판·배치·목표선택,다시보고싶은공간설명 | 장식클릭수만으로애착판정불가 |
| 고객을 이해하는가 | 놓친수요원인확인후적합한행동변화 | 보고창열람만으로학습판정불가 |
| 이익을 구분하는가 | 매출·변동비·고정비를설명하는지 | 순이익높음이개념이해를보장하지않음 |
| 선택이 의미있는가 | 옵션분포·후속결과인식·다른전략시도 | 균등분포가목표는아님 |
| 경쟁이 납득되는가 | 패배이유설명·회복시도·상권이동요청 | 승자의만족도만보면편향 |
| 돌아올 이유가 있는가 | 종료시다음목표·후속접속에서목표재개 | 보상강요와자발적목표를구분 |
| 교육적 전이가 있는가 | 새사례에서원가·적합성·납기설명 | 소규모표본결과를일반화하지않음 |

## 초기 관측 이벤트

공통 명령과 확정 이벤트의 이름은 구현 문서를 원본으로 사용한다. 분석용 집계는 같은 원장·상태에 연결하되 분석 이벤트 수신 여부로 보상을 결정하지 않는다.

- 업종 선택 초안·확정·연습 진입.
- 최초 작업 수락·시작·납품·취소와 원인.
- 개점·마감·예고 영업 이행·불이행.
- 수요 노출·후보·선택·외부 이탈의 집계.
- 연구 시작·완료·적용, 유지보수, 목표 설정.
- 선택 제시·결정·후속 결과·회고 확인.
- 연결 복구·유예 만료·서버 원인 중단.
- 상품 조회·결제 상태·DG 지급·정정의 운영 지표.

계정 식별자는 분석에 필요한 수준으로 최소화하고, 자유 대화 원문을 교육 점수 계산에 사용하지 않는다. 참여자의 의도나 능력을 행동 몇 번으로 단정하지 않는다.

## 비교 방법

경제 균형 테스트는 동일 seed·초기 자산·운영 시간으로 비교한다. 사용자 테스트는 업종과 이전 타이쿤 경험을 함께 기록한다. 업데이트 전후 차이를 볼 때 튜토리얼·가격·수요·아트가 한 번에 바뀌면 어떤 변경의 영향인지 구분하기 어렵다.

초기 테스트의 합격 비율을 임의로 정해서 성공을 선언하지 않는다. 관측된 막힘과 핵심 불변식 위반을 먼저 고치고, 충분한 기준 데이터가 쌓인 뒤 재방문·구매 전환·학습 지표의 목표를 세운다.

## 중단 또는 재설계 신호

- 플레이어가 특정 업종을 현실의 낮은 지위·높은 지위로 해석한다.
- 자주 접속하지 않았다는 이유만으로 회복 불가능한 손실을 경험한다.
- 선택지의 설명과 실제 비용·후속 결과가 다르다.
- 한 번 실패하면 DG 구매만이 해결책처럼 보인다.
- 최저가·한 가지 연구·상시 개점만이 반복해서 우세하다.
- 품질을 개선해도 실제 결과가 바뀌지 않거나 원인을 알아볼 수 없다.

이런 경우 콘텐츠 양을 늘리기보다 고객·비용·피드백·선택 모델을 수정한다.
