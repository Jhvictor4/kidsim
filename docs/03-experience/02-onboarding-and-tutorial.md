# 업종 선택과 튜토리얼 상태 설계

[전체 문서 트리](../README.md) · [상위 분야](README.md)

> 문서 ID: EXP-02 · 버전: 2.0 · 기준일: 2026-11-11 · 상태: 구현 전 제작 기준안

## 목표와 완료 조건

플레이어가 업종을 고르고, 고객의 조건을 확인하고, 매출과 비용을 구별하고, 선택의 결과를 본 뒤 정상적으로 마감할 수 있게 한다. 최초 완료는 계정에 한 번 기록한다. 튜토리얼 완료 보상은 XP20이며 별도 TC 보너스는 없다. 첫 정상 거래의 매출·원가·XP는 경제 원본대로 한 번만 처리한다.

튜토리얼은 12개 상태로 구성한다. 연출을 넘기는 것과 경제적 행동을 실행하는 것을 구분한다. 숙련자는 설명을 접을 수 있지만 시작 자산과 완료 보상을 다시 받을 수 없다.

## 상태별 명세

| 상태 | 화면과 플레이어 행동 | 서버 완료 기준 | 생략·중단·복구 |
|---|---|---|---|
| TUT00 | 로딩, 접근성·조작 설정, 이어 하기 | 프로필 정상 로드, 활성 사업·튜토리얼 상태 확보 | 로드 오류 시 신규 프로필 생성 금지 |
| TUT01 | 4개 업종 카드와 짧은 작업 미리보기 | 선택 초안 저장. 아직 사업 생성·TC 지급 없음 | 확정 전 자유 변경 |
| TUT02 | PB120으로 시범 운영 견적 선택 연습 | 예산 내 옵션 선택과 조건 설명 확인 | 연습 건 하나를 재개. PB를 TC로 전환하지 않음 |
| TUT03 | 업종·가게 이름·기본 테마 최종 확인 | 사업 생성과 초기 TC80·필수 설비·PB연습 종료를 중복 없이 기록 | 응답 유실 시 같은 사업 ID 반환 |
| TUT04 | 이동·작업 접점·장식 배치 확인 | 실제 입력과 유효 배치 또는 기본 배치 유지 확인 | 모터 조작 도움과 버튼 대안 |
| TUT05 | 영업 상태, 약속, 예상 비용 확인 후 개점 | 유효한 상태 전이와 영업 자금 조건 충족 | 못 열면 부족 조건 표시. 유료 구매 유도 없음 |
| TUT06 | 훈련 고객의 필요 확인, 첫 작업 수락·착수 | 원가·운영비 예약과 작업 상태 확정 | 동일 고객·작업 ID로 재개 |
| TUT07 | 업종별 공정과 필요한 선택 사건을 수행하고 전달 또는 검수 | 해당 거래의 납품과 원장 정산 확정 | 화면 연출만으로 완료 처리 금지 |
| TUT08 | 첫 거래 보고: 매출·원가·고정비·순변화 | 잔여 작업을 정리해 CLOSED에서 최초 보고 열람. 정산 값은 원장 조회 | 첫 보고 중 신규 접수·운영비 없음 |
| TUT09 | 첫 선택 사건 또는 이미 수행한 선택의 회고 | 최초 사건 기록이 있으면 회고, 없으면 선택 확정과 즉시 관측 결과 확인 | 재접속으로 옵션 다시 뽑기 금지 |
| TUT10 | 연구 2갈래와 설비 성장 비교, 다음 목표 저장 | 목표 ID 저장. 실제 연구·구매를 강요하지 않음 | 자금이 없어도 완료 가능 |
| TUT11 | 신규 주문 차단, 잔여 업무 정리, 마감과 회고 | CLOSED, 첫 완료 플래그, XP20 한 번 확정 | 거래 결과 저장 중이면 처리 중 표시 |

TUT06~TUT09의 구체적인 화면과 분기는 각 업종의 스토리보드를 따른다. 튜토리얼 상태와 장면 번호는 일대일 관계가 아니며 하나의 상태가 여러 컷으로 표현될 수 있다. SI의 추가 범위 사건은 첫 계약 수행 중 TUT07에서 먼저 발생할 수 있다. 이 경우 TUT09는 저장된 선택과 후속 결과를 회고하며, 이미 납품한 계약을 다시 수정하지 않는다. 튜토리얼 안내 상태와 거래·선택 상태는 별도의 축이다. TUT09는 선택 확정과 즉시 관측 가능한 결과의 회고로 완료한다. 다음 실제 고객의 경험 같은 지연 효과는 pendingEffect로 남겨 일반 플레이에서 이어 가며, 새 손님을 기다려야 튜토리얼이 끝나는 조건을 만들지 않는다. 연습용 고객 동의 응답은 거래·XP·명성 보상 없이 사용할 수 있다.

## PB 연습의 역할

PB는 지원실에서 제공하는 ‘시범 운영 계획’의 예산이다. 120PB 안에서 비용과 조건을 비교하는 연습에 쓴다. 장비 운반을 맡아 비용을 줄이거나, 준비 서비스를 포함하거나, 이용 시간을 조절하는 선택을 보여 준다. 각 옵션의 확정 비용·조건은 경제와 선택 사건의 콘텐츠 정의를 사용한다.

이 연습의 소품은 실제 사업의 장비가 아니며 TC·DG·영구 성능을 만들지 않는다. 남은 예산은 연습 종료 때 소멸한다. 실제 사업을 만들 때 지급되는 80TC와 무료 필수 설비는 업종마다 같은 권리로 제공한다.

## 최초 거래와 일반 시장의 구분

훈련 고객은 공유 경쟁 수요에서 빼앗지 않는다. `origin=TRAINING`과 `trainingMode=ONBOARDING|PRACTICE`로 식별하며, 최초 ONBOARDING 거래 자격을 별도로 확인한다. 이 중 계정당 최초 거래만 정상 초기 보상을 받을 수 있다. 반복 연습은 지갑·XP·명성·아이템을 바꾸지 않는다. 일반 시장에서는 이런 고객 보장 기능이 없다.

정산 보고에 표시할 예시는 ‘시작80 + 매출 − 실제 소모 원가 − 실제 누적 운영비 − 그 밖에 스스로 지출한 금액’이다. 임의의 고정 최종 잔액을 약속하지 않는다. 이미 지출한 TC와 아직 예약된 TC를 구분한다.

## 선택형 안내 대사

하나: “가게가 바쁘면 매출은 늘어요. 그동안 쓴 돈도 같이 살펴볼까요?”

모루: “연구를 먼저 할 수도 있고, 지금 장비를 잘 관리할 수도 있어요. 어떤 손님을 만족시키려는지부터 정해 보세요.”

단: “지금 마감하면 새 손님은 받지 않아요. 이미 맡은 일은 끝내거나, 취소했을 때의 결과를 확인해야 해요.”

대사는 정답 선택을 칭찬하는 대신 선택한 조건과 실제 행동을 연결한다. 다른 선택을 했다는 이유로 인격이나 능력을 평가하지 않는다.

## 막힘 방지

- 목표 표시에는 목적지뿐 아니라 현재 부족 조건을 적는다.
- 새 UI가 열리면 이미 눌러 둔 버튼의 입력을 재사용하지 않는다.
- 최초 조작 설명과 정산 보고는 신규 접수를 막고 잔여 작업을 정리한 CLOSED에서 읽는다. 이 설명을 읽는 시간에 운영비나 새 사건을 만들지 않는다. 실제 선택 사건이 PRESENTED가 된 뒤에는 콘텐츠의 활동 60초 기한을 표시하고 그대로 적용하며, 화면을 닫았다는 이유로 무한히 연장하지 않는다.
- 자금 부족은 기본 보유 물건을 다시 구매하게 하지 않고 예약·소모·지출 내역으로 설명한다.
- 단계가 바뀌기 전에 필요한 상태를 먼저 저장한다.
- 영구 업종 변경은 MVP에 없음을 확정 화면에 알린다. 네 업종의 무보상 연습은 계속 이용할 수 있다.

## 완료 검증

F01~F04 및 F20을 적용한다. 각 상태에서 앱을 닫았다가 돌아오는 경우를 검증한다. 최초 보상은 한 번이며 훈련 수요가 일반 고객 배분 통계에 섞이지 않아야 한다. 사업을 확정하기 전 업종 선택 취소는 어떤 영구 비용도 만들지 않는다.
