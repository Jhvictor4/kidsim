## 화면 구조

| 화면 | 항상 알아야 하는 정보 | 주요 행동 | 서버 확인이 필요한 결과 |
|---|---|---|---|
| 사업 선택 | 업종·대표 고객·작업·변경 제한 | 연습·선택·확정 | 사업 생성과 초기 자산 |
| 운영 HUD | 영업 상태·사용 가능 TC·예약 TC·현재 업무 | 열기·마감·작업·도움말 | 영업·원가·납품 |
| 고객 카드 | 요구·가격·대기·완료 약속 | 수락·거절·세부 조건 | 수요 예약과 슬롯 |
| 제품과 공정 | 실제 품질·시장 적합성·공정 원인 | 점검·유지보수·제품 설정 | 상태·재료·작업 |
| 연구 | 2갈래·선행 조건·비용·시간·예상 변화 | 시작·진행 확인·적용 | 비용과 연구 효과 |
| 사건 선택 | 발생 원인·현재 정보·옵션·비용·기한 | 선택·결과 확인 | 결정 ID와 후속 효과 |
| 상권 | 공개 가격·대기·고객 분포·내 개선 이유 | 관찰·자기 전략 수정 | 비공개 정보 접근 없음 |
| 꾸미기 | 보유 수량·설치 가능성·외형 | 배치·회전·회수·테마 | 보유와 배치 revision |
| 경영 보고 | 매출·변동비·고정비·연구비·순변화 | 원인 보기·다음 목표 | 원장 기반 합계 |
| 마감 | 새 주문 차단·남은 일·취소 결과 | 기다리기·명시 취소·퇴장 | CLOSED와 정산 완료 |

## 기본 조작

PC는 이동 키와 클릭·상호작용 키를 제공하고, 터치는 이동 패드와 큰 행동 버튼으로 같은 기능을 제공한다. 정확한 키 배치는 플랫폼 어댑터에서 결정하되 화면에 현재 바인딩을 표시한다. 모든 드래그 작업에는 선택 후 버튼으로 옮기는 대안을 둔다.

장식 배치에서는 미리보기와 확정을 분리한다. 취소는 보유 아이템을 없애거나 TC를 차감하지 않는다. ‘구매’와 ‘배치’는 서로 다른 행동이며, 이미 가진 물건을 놓으려다 다시 결제하지 않게 한다.

## 처음 시작하기

1. 네 업종의 고객과 작업 방식을 살펴본다. 확정 전에는 선택을 바꿀 수 있다.
2. PB 연습에서 비용과 조건을 비교한다. PB는 연습용이며 내 사업 자금과 다르다.
3. 업종과 간판을 확정하면 80TC와 기본 설비로 시작한다.
4. 기본 배치와 통로를 확인하고 영업을 연다.
5. 고객의 요구와 감당할 수 있는 비용을 확인한 뒤 일을 맡는다.
6. 거래를 마치고 매출·원가·운영비를 확인한다.
7. 개선할 점 하나를 골라 연구 또는 운영 목표로 저장한다.
8. 떠나기 전 마감 화면에서 남은 일을 확인한다.

## 손님이 오지 않을 때

먼저 영업 상태와 고객을 받을 자리가 있는지 확인한다. 다음으로 공개 가격, 제품의 고객 적합성, 실제 품질, 대기, 최근 서비스 결과를 본다. 보고 화면은 ‘방금 놓친 수요의 관측 이유’를 보여 준다. 모든 손님을 반드시 얻는 업그레이드는 없다.

카페와 음식점은 고객이 원하는 맛·식사 조건·대기 상황을 확인한다. 소프트웨어는 요구 기능과 검증된 제품 상태를, SI는 범위·납기·검수 조건과 현재 여력을 확인한다. 다른 업종의 거래 건수만 보고 내 사업이 실패했다고 판단하지 않도록 단위와 관측 시간을 함께 표시한다.

## 문을 닫는 방법

마감을 선택하면 새 고객을 받지 않는다. 맡은 일이 남아 있으면 CLOSING 상태로 정리한다. 착수한 일을 취소하면 이미 소모한 원가와 약속의 결과가 남을 수 있으므로 취소 확인 화면에 내역을 보여 준다. 정상적으로 CLOSED가 된 뒤에는 미접속 시간 때문에 운영비·품질·명성이 계속 줄지 않는다.

닫은 채로 연구할 수 있다. 영업 예고에 고객 예약이 확정되었다면 변경·취소 가능 조건을 먼저 확인한다. 확정 예약 없이 게시만 한 영업 예고는 철회할 수 있고, 고객 없는 정상 휴업에는 명성 벌점을 주지 않는다. 닫혀 있다는 사실 자체와 예고한 약속을 어긴 사실은 다르게 취급한다.

## 돈의 표시

HUD의 첫 숫자는 ‘지금 쓸 수 있는 TC’다. 펼치면 총 TC, 재료 예약, 운영비 예약, 이미 소모한 비용을 보여 준다. 예약한 돈은 사라진 돈이 아니며 해당 작업의 비용을 감당하기 위해 다른 구매에 쓰지 못하는 상태다.

DG는 테마·외형·배치 프리셋에 사용한다. 실제 구매 가격은 결제 제공자가 확인한 상품 정보를 보여 주며, 성공 페이지를 봤다는 이유만으로 DG를 먼저 지급하지 않는다. 처리 중이면 현재 주문 상태를 조회할 수 있다.

PB는 해당 연습 또는 의뢰 화면에만 표시하고 개인 지갑 옆에 합산하지 않는다. XP는 성장값이며 소비 버튼이 없다.

## 사건에 대처하기

선택 화면에서 이미 아는 조건, 바로 지불할 비용, 추가 작업 또는 약속을 확인한다. 결과가 확정되면 선택한 경로를 기록한다. 재접속으로 다른 결과를 뽑을 수 없다. 자금이 부족할 때에도 적어도 하나의 실행 가능한 비유료 대안을 제공한다.

경량 모델을 사용하는 경우에도 게임의 비용·효과는 정해진 사건 정의가 결정한다. 문장이 바뀌었다고 비용이나 정답이 달라지지 않는다.

## 경쟁과 소통

다른 사업의 공간을 방문하고 공개된 제품과 가격을 관찰할 수 있다. MVP의 소통은 지정 문구·감정 표현·방문 요청·개장 안내를 중심으로 한다. 자유 입력 대화를 추가하려면 별도의 필터·신고·차단·연령 정책을 완료해야 한다.

다른 사람의 영업을 막거나 허위 평점으로 명성을 떨어뜨리는 기능은 없다. 명성은 게임이 확인한 거래 결과로 계산한다. 공개 방문을 끄더라도 NPC 영업 자격과 성장 기회는 유지한다.

## 연결·복구 화면

연결이 끊기면 ‘다시 연결 중’과 남은 60초 복귀 유예를 표시한다. 이때 새 경제 입력을 확정된 것처럼 보여 주지 않는다. 다시 연결되면 서버 스냅샷으로 상태를 맞춘다. 유예가 끝난 경우에는 어떤 작업이 완료·취소·보류되었는지 먼저 설명한다.

서버 장애로 생긴 중단은 사용자 과실로 표시하지 않는다. 저장 상태를 확인할 수 없을 때는 재구매를 권하지 않고 거래 조회와 복구 안내를 제공한다.

## 접근성과 화면 검증

| ID | 검증 내용 |
|---|---|
| U01 | 색을 보지 못해도 영업·품질·예약 상태를 글자와 아이콘으로 구별 |
| U02 | 키보드만으로 핵심 흐름과 선택·취소·마감 수행 |
| U03 | 터치에서 버튼 겹침·스크롤 오입력·드래그 강요 없음 |
| U04 | 글자 확대 시 비용·선택지·확정 버튼이 잘리지 않음 |
| U05 | 움직임 감소 옵션에서 카메라 연출을 생략하고 기능 유지 |
| U06 | 처리 중·실패·복구·이미 완료 상태를 구별 |
| U07 | 매출과 순이익, 총 TC와 사용 가능 TC를 구별 |
| U08 | ‘연습’, ‘일반 시장’, ‘실화폐 구매’를 명확히 구별 |

각 화면의 최종 입력 크기와 대비는 실제 대상 기기에서 검증한다. 화면 시안만으로 접근성 완료를 선언하지 않는다.
